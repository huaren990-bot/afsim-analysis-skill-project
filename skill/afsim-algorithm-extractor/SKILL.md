# AFSIM 算法提取 Skill

本 skill 负责从 AFSIM 源码中抽取可理解、可验证、可迁移的算法和功能单元。

## 输入

- AFSIM 源码片段或源码目录。
- `workspace/source-index/` 中的索引。
- 用户指定的目标算法、模块或功能。
- 自有项目的目标接口，若用户已提供。

## 执行步骤

1. 定位候选源码：优先使用索引，再用符号名、注释、调用链和文件路径补充搜索。
2. 区分三类内容：算法核心、工程封装、框架依赖。
3. 抽取输入、输出、状态变量、单位、边界条件和错误处理。
4. 将关键数值计算转换为数学表达或清晰伪代码。
5. 建立代码变量到数学符号的映射表。
6. 评估可移植性：高、中、低，并说明原因。
7. 给出验证方案：单元测试、数值对比、场景回放或边界测试。

## 输出

- `docs/algorithms/<domain>-<algorithm>-card.md`
- `workspace/extracted-algorithms/<algorithm>/pseudocode.md`
- `workspace/extracted-algorithms/<algorithm>/interface-spec.md`
- 必要时生成 `workspace/extracted-algorithms/<algorithm>/prototype.*`

## 伪代码规范

伪代码输出必须遵循以下格式：

- **语言**：伪代码使用英文标识符（变量名/函数名/算法名），但每条注释和说明必须使用**中文**。每行伪代码应有对应的中文注释解释其物理意义或计算目的。
- **格式**：伪代码块用 ` ``` ` 包裹，结构体使用类 C/类 Python 语法。
- **注释模板**：
  - 算法开头用中文说明整体目标和调用上下文。
  - 每一步/每一阶段用中文说明该步在做什么（如 `// 预测步：用 F₀ 推进到临时中间状态`）。
  - 关键物理量标注单位和物理意义（如 `a_body = F_body / mass   // 体轴加速度 = 牛顿第二定律 (m/s²)`）。
  - 边界条件/保护限幅说明其数值原因和使用的阈值来源。
- **最低注释密度**：伪代码中每 3-5 行至少有一行中文注释。

## 算法卡片规范（中文注释全覆盖）

算法卡片是本 skill 的主要人可读产物，所有引用源码、调用链、伪代码、变量映射等部分都必须添加中文注释：

### Source Locations 表

每条源码位置必须附 "中文说明" 列，简要说明该函数/符号在算法中的作用：
- 示例：`P6DofIntegrator::Update() | 31-115 | 积分器主循环实现 — Heun 预测-校正全流程（质量更新→预测→平均→校正→后处理）`

### Entry Point & Call Chain（调用链）

调用链中的每一行必须附带中文注释，说明该步在算法流程中的作用：
- 示例：`→ CalculateFM()  // 第一步：计算当前力/力矩（气动+推进+起落架+重力）`

### 输入/输出/内部状态表

已有 "Meaning" 列的基础上，新增 "中文说明" 列，对关键物理量补充物理解释和注意事项。

### 依赖项表

已有 "Description" 列的基础上，新增 "中文说明" 列，说明每个依赖在算法中的角色和调用上下文。

### Pseudocode（伪代码）

遵循上述 "伪代码规范" 的全部要求。伪代码块中每条注释必须使用中文。

### Variable Mapping（变量映射表）

已有 "Meaning" 列的基础上，新增 "中文说明" 列，解释每个变量的物理含义、在公式中的角色或数值来源。

## interface-spec.md 规范（接口规格中文注释）

接口规格文件也必须添加中文注释：
- 每个 `struct` / `class` 开头的注释说明其总体接口职责。
- 每个方法和成员变量附带中文注释说明其物理意义和单位。
- 典型调用示例（示例代码块）中的每行/每段代码附带中文注释。

## 算法卡片必须包含

- 算法名称和领域。
- 源码位置。
- 入口函数和调用链。
- 输入、输出、状态依赖。
- 数学形式或伪代码。
- 变量映射。
- 框架依赖和可替换依赖。
- 可移植性评分。
- 测试和验证计划。

## 迁移前限制

如果许可证不明确，或算法与 AFSIM 框架高度耦合，应输出 clean-room 风格的算法说明，而不是直接复制源码实现。
