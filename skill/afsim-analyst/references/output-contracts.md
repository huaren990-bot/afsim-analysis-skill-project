# Output Contracts

Use these structures to keep outputs consistent.

## Architecture Report

Required sections:

- Scope and inputs
- Source roots analyzed
- Top-level module map
- Simulation lifecycle
- Data flow
- Configuration flow
- Extension points
- Key classes and ownership
- Unknowns and follow-up checks
- Source evidence

## Algorithm Card

Required fields:

- Algorithm name
- Domain
- Purpose
- Source locations
- Entry points
- Inputs
- Outputs
- Internal state
- External dependencies
- Mathematical form
- Pseudocode
- Variable mapping
- Edge cases
- Portability score: high, medium, or low
- Extraction strategy
- Validation plan

## Requirement Gap Report

Required fields:

- Requirement ID
- Requirement text
- Target project evidence
- AFSIM evidence
- Status: satisfied, partially satisfied, missing, unknown
- Missing atomic capabilities
- Candidate AFSIM modules
- Recommended next action

## Migration Record

Required fields:

- Feature name
- Requirement IDs
- Candidate AFSIM source
- Selection rationale
- Coupling assessment
- Interface assumptions
- Adaptation steps
- License and attribution notes
- Test plan
- Review status
