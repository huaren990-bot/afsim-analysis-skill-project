# AFSIM 总控分析 Skill

本 skill 是 AFSIM 分析体系的总控入口。它不负责把所有细节一次性塞进上下文，而是根据任务目标调用或参考项目中的专项 skill，让大模型逐步完成“快速认知 AFSIM -> 定位功能 -> 提取算法 -> 适配自有项目 -> 沉淀知识库”的完整流程。

## 核心定位

- 快速判断用户当前任务属于源码认知、架构分析、算法提取、需求映射、迁移生成还是文档沉淀。
- 读取用户提供的基准文件，并把它作为后续所有分析和生成工作的依据。
- 选择合适的专项 skill，并规定输入、输出、证据和验收标准。
- 保证所有结论可追溯到源码、需求文档或已有分析产物。
- 将分散的分析结果整理成可复用的 AFSIM 知识资产。

## 专项 Skill 分工

项目中推荐保留以下专项 skill：

| Skill | 职责 | 适用任务 |
| --- | --- | --- |
| `afsim-source-cognition` | AFSIM 源码快速认知、目录扫描、模块职责、调用链和数据流学习 | “帮我理解 AFSIM 某模块”“生成总体架构” |
| `afsim-algorithm-extractor` | 从源码中识别、解释、抽取数学公式和算法逻辑 | “提取制导算法”“把传感器模型转成伪代码” |
| `afsim-requirement-mapper` | 将自有项目需求与 AFSIM 能力做映射和缺口分析 | “我的项目缺哪些功能”“AFSIM 哪些模块能补齐需求” |
| `afsim-migration-builder` | 生成可落地的迁移方案、接口适配和测试计划 | “把这个算法用到我的项目”“生成迁移计划” |
| `afsim-knowledge-curator` | 整理知识库、索引、报告、决策记录和追溯矩阵 | “沉淀分析结果”“更新知识库” |

当用户请求覆盖多个阶段时，按上表从上到下组合使用；当用户只问单点问题时，只使用最小必要的专项 skill。

## 标准工作流

1. **读取基准材料**
   - 优先读取用户指定的文档、源码路径、自有项目文件和历史分析产物。
   - 明确本轮任务的输入范围，不臆测未提供的源码结构。
   - 对skill中涉及到unkonw或未覆盖的内容进行询问是否补充。
2. **建立认知索引**
   - 使用 `afsim-source-cognition` 生成文件、模块、类、函数、调用关系和数据流索引。
   - 机器可读结果写入 `workspace/source-index/`。
   - 人可读结果写入 `docs/architecture/`。

3. **提取算法和功能**
   - 使用 `afsim-algorithm-extractor` 识别公式密集区、仿真流程关键点和可移植算法。
   - 每个算法必须形成算法卡片，说明源码位置、输入输出、变量映射、数学形式、伪代码、依赖项和验证方法。
   - **中文注释规范**（适用于算法卡片、伪代码和接口规格）：
     - 算法名和变量名使用英文，所有注释和说明使用**中文**。
     - 算法卡片的 Source Locations 表、调用链、依赖项表、变量映射表必须新增"中文说明"列，解释每条记录在算法中的作用。
     - 伪代码中每 3-5 行至少一条中文注释，标注物理意义、单位和计算目的。
     - 接口规格中的每个结构体、方法、成员变量和调用示例均须附带中文注释。

4. **映射自有项目需求**
   - 使用 `afsim-requirement-mapper` 将需求文档、自有项目源码或接口定义与 AFSIM 能力对齐。
   - 产出“已满足、部分满足、缺失、未知”四类结论。

5. **生成可落地迁移方案**
   - 使用 `afsim-migration-builder` 对候选 AFSIM 实现做耦合度、许可证、接口适配、测试成本评估。
   - 先生成迁移方案和接口假设，再生成代码或伪代码。

6. **沉淀知识并闭环**
   - 使用 `afsim-knowledge-curator` 更新报告、索引、追溯矩阵和决策记录。
   - 避免重复生成互相割裂的文档；优先更新已有产物。

## 输出规则

- 架构认知输出到 `docs/architecture/`。
- 算法提取输出到 `docs/algorithms/` 和 `workspace/extracted-algorithms/`。
- 需求映射输出到 `docs/requirements/`。
- 迁移方案输出到 `docs/migration/`。
- 过程记录、人工审查意见和未决问题输出到 `docs/records/`。
- 索引、缓存和中间产物输出到 `workspace/`。

## 证据规则

- 任何关于 AFSIM 行为的判断，必须尽量标注源码文件、符号名和行号范围。
- 任何关于自有项目缺口的判断，必须标注需求来源或目标项目源码依据。
- 无法直接证明的内容标记为“推断”或“待确认”。
- 不记录隐藏推理过程；只记录可审查的证据、假设、决策、结论和风险。

## 迁移原则

- 优先提取算法思想、数学公式、接口契约和小型独立函数。
- 不直接搬运强耦合框架代码，除非用户明确要求且许可证允许。
- 许可证不明确时，生成 clean-room 风格的算法说明和重新实现建议。
- 生成代码前先给出接口假设、依赖清单和验证计划。
- 生成的代码应遵循自有项目现有风格、构建系统和测试方式。
