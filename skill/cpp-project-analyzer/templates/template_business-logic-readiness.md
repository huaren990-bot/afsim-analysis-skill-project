# business-logic-readiness.md 模板

## 要求

面向下一步 AFSIM 业务逻辑分析的承接文档。本文档不直接给出最终业务逻辑结论，而是把可继续深入的业务域、端到端流程、规则/决策点、输入输出和源码证据组织成可执行入口。

所有业务含义必须有证据。只有目录名、类名或单一弱证据支持时，必须标记为 `inferred`；无法确认时标记为 `unknown` 并写明人工确认问题。

## 填写规则

1. 每条业务域、流程或规则候选至少引用一类证据：`docs/architecture/module-overview.md`、`source-index/function-index.jsonl`、`source-index/dependency-index.jsonl`、`docs/architecture/lifecycle.md`、`docs/architecture/dataflow.md`、`docs/architecture/extension-points.md` 或具体源码位置。
2. 所有候选必须填写 `evidence_level`，取值只能为 `direct`、`cross_checked`、`inferred`、`unknown`。
3. 端到端流程必须尽量覆盖“触发入口 → 配置/事件输入 → 关键处理链 → 状态对象 → 输出/副作用”；缺失环节必须写在“下一步分析问题”中。
4. 业务规则/决策点必须说明条件、所在函数/类和影响对象；没有条件或分支证据时不得写成确定规则。
5. 数据与配置映射必须把输入、解析/接收函数、运行时状态和输出影响连起来；任一环节未知时标记 `unknown`。
6. 边界外 training/demo/test/doc/tooling 不得作为核心业务逻辑证据，除非用户明确要求纳入。
7. 未知项必须可处理，包含建议人工确认的问题和对象/文件。
8. 不得使用省略号省略候选；超过 30 条时正文列优先级最高的条目，并链接完整清单文件。
