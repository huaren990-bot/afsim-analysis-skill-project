# context-handoff.md 模板

## 用途

阶段间上下文传递的标准格式。每个阶段完成后，分析 Agent 必须填写此文件，作为下游阶段的输入契约。
文件命名：`project-boundary/context-handoff-phase<N>.md`

## 结构

```markdown
# Phase <N> 上下文传递

> **完成日期**：
> **分析 Agent**：<skill name>
> **验证 Agent**：<skill name>
> **验证结果**：✅ 通过 / ⚠️ 部分通过 / ❌ 不通过（重试后）

---

## 1. 本阶段产出文件清单

| 文件名 | 路径 | 行数/条目数 | 说明 |
|--------|------|-----------|------|
| xxx.jsonl | `source-index/xxx.jsonl` | xxx 行 | xxx |
| yyy.md    | `architecture/yyy.md`    | —         | xxx |

---

## 2. 验证报告摘要

| 检查项 | 结果 | 备注 |

| 检查 2 | ✅/❌ | ... |
| ...    |      | ... |

---

## 3. 下游阶段输入契约

下游阶段（Phase <N+1>）启动时，**必须**读取以下文件：

- [ ] `<路径1>` — 用途：xxx
- [ ] `<路径2>` — 用途：xxx
- [ ] `<路径3>` — 用途：xxx

---

| 指标 | 值 |

| 模块数 | xxx |
| 仍为 unknown 的项数 | xxx |
```

## 填写规则

1. 每个阶段完成后**必须**填写此文件，不可跳过。
2. "下游阶段输入契约"中列出的文件必须是真实存在且可读取的。
3. "已知问题与限制"必须诚实记录，不可隐瞒。
4. 验证报告摘要必须与实际验证报告一致。
5. 关键统计数据必须与产出文件实际行数/条目数一致。
